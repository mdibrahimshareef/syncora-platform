## 3. Current Architecture & Component Inventory

### AI Core & Orchestration
- `src/lib/ai/provider.ts`: Vercel AI SDK integration supporting OpenAI (`gpt-4o-mini`), Google Gemini (`gemini-3.5-flash`), or `mock` fallback. Also provides embedding models (`text-embedding-3-small`, `gemini-embedding-2`).
- `src/lib/ai/orchestrator.ts`: Streams responses via `streamText`, normalizes message parts, bounds history to 15 turns, executes tools with `stopWhen: isStepCount(maxSteps)`, logs telemetry, and records usage.
- `src/lib/ai/context.ts`: Hybrid retrieval using keyword regex matching against `projects`, `workspace_members`, `tasks`, and semantic vector search via `match_embeddings` RPC.
- `src/lib/ai/tools.ts`: 15 read-only and proposal tools. Read-only: `get_workspace_summary`, `get_workspace_insights`, `get_my_work`, `get_projects`, `get_documents`, `search_tasks`, `get_task`, `get_overdue_tasks`, `get_blocked_tasks`, `get_project`, `get_project_health`, `get_project_milestones`, `get_team_workload`, `get_time_entries`, `get_automation_status`. Proposals: `generate_workflow_plan`, `create_task`, `update_task`, `assign_task`.
- `src/lib/ai/action-executor.ts` & `src/lib/ai/workflow-executor.ts`: Deterministic mutation execution and multi-step plan execution guarded by idempotency keys, leases, post-action verification, and user approval.
- `src/lib/ai/governance.ts`: Workspace policy validation (`ai_workspace_policies`), rate limiting, capability toggles, and usage recording (`ai_usage_metrics`).
- `src/lib/ai/dispatcher.ts`: Atomic background job claimer using Postgres `claim_ai_job(p_executor_id, p_limit)` with `FOR UPDATE SKIP LOCKED`.

### Existing Data Model
- **Workspaces & Members**: `workspaces`, `workspace_members`, `profiles`, `organizations`, `organization_members`.
- **Work Management**: `projects`, `tasks`, `subtasks` (`parent_id`), `task_dependencies`, `milestones`, `documents`, `time_entries`, `goals`, `initiatives`, `portfolios`, `portfolio_projects`.
- **AI & Automation**: `ai_conversations`, `ai_messages`, `ai_workflows`, `ai_workflow_events`, `ai_action_logs`, `ai_workspace_policies`, `ai_usage_metrics`, `ai_jobs`, `ai_insights`, `automations`.
- **Search & Embeddings**: `embeddings` table with vector index, `match_embeddings` RPC.

## 4. Release 4.6 Gaps & Requirements

1. **Organizational Memory Model (Phases 1-2)**:
   - Current system only saves transient conversation messages in `ai_conversations` / `ai_messages`.
   - Missing: Structured, permission-scoped organizational memory (`ai_memories` table) distinguishing **workspace memory** (shared, authorized members) from **user memory** (private preferences) and short-term conversation context.
   - Missing: Typed memory categories (goals/priorities, project objectives, explicit decisions & rationale, recurring blockers, historical outcomes, working agreements, user preferences).
   - Missing: Lifecycle operations (create, retrieve, supersede, archive, expire), provenance tracking, and deduplication.

2. **Workspace Relationship Understanding (Phase 3)**:
   - Current retrieval only fetches flat lists (5 projects, 10 tasks) without traversing connected entity graphs.
   - Missing: Relationship-aware traversal connecting `Goal -> Project -> Milestone -> Task Dependencies -> Blocked Tasks -> Assignee Workload -> Historical Outcomes`.
   - Must use bounded SQL queries in existing PostgreSQL without introducing an external graph DB.

3. **Temporal Reasoning & Risk Propagation (Phase 4)**:
   - Current `time.ts` provides basic server date strings; `health.ts` does simple task counts.
   - Missing: Time-aware risk analysis detecting approaching deadlines without progress, dependency chain delay propagation, stalled milestones, velocity changes, and clear uncertainty communication for predictions.

4. **Hybrid Retrieval & Evidence Fusion (Phase 5)**:
   - Missing: Typed internal evidence representation combining structured SQL, semantic vector search, workspace memory, and relationship graph.
   - Missing: Source authority hierarchy ensuring authoritative current database facts take precedence over stale historical memory or semantic summaries.
   - Missing: Grounded source citations validated against user authorization.

5. **Memory-Aware Conversations (Phase 6)**:
   - Integrate bounded, permission-scoped memory retrieval into `orchestrator.ts` and `getWorkspaceContext`.
   - Prevent private user preferences from leaking into workspace responses or across users.

6. **Explainable Decision Support & Action Boundary (Phase 7)**:
   - Implement structured decision comparison (`situation`, `evidence`, `constraints`, `options`, `trade-offs`, `recommendation`, `uncertainty`).
   - Route proposed mutations strictly through established workflow/governance channels without direct database writes.

7. **Outcome & Feedback Loop (Phase 8)**:
   - Track recommendation outcomes: accepted/rejected, execution result, observed state changes (blocker resolved, deadline met/missed).
   - Link feedback to decision support without bypassing governance or silently modifying permissions.

8. **AI Evaluation Framework & Security Hardening (Phases 9-10)**:
   - Build a comprehensive, repeatable evaluation suite in Vitest.
   - Golden test scenarios for workspace isolation, memory scoping, temporal reasoning, prompt injection, and hallucination resistance.

## 5. Implementation Roadmap (Phases 1–15)

1. **Phase 1 & 2**: Create typed organizational memory model, Supabase migration `00062_ai_organizational_memory.sql`, RLS policies, and server-side memory manager (`src/lib/ai/memory.ts`).
2. **Phase 3**: Build relationship understanding engine (`src/lib/ai/relationships.ts`) and register relationship tools (`get_dependency_graph`, `get_goal_alignment`).
3. **Phase 4**: Implement temporal reasoning and dependency risk propagation engine (`src/lib/ai/temporal-reasoning.ts`).
4. **Phase 5**: Implement evidence fusion engine (`src/lib/ai/evidence-fusion.ts`) enforcing source authority rules (current state > memory > summaries).
5. **Phase 6**: Integrate memory-aware context into `orchestrator.ts` and `context.ts` with bounded token budgets and user privacy guards.
6. **Phase 7 & 8**: Create structured decision support contracts and outcome feedback recording (`src/lib/ai/decision-support.ts`, `src/lib/ai/outcomes.ts`).
7. **Phase 9 & 10**: Build evaluation test suite and security/red-team scenarios in `tests/ai/evals/`.
8. **Phase 11 & 12**: Performance controls, timeout safeguards, and AI chat UI enhancements (memory provenance, decision cards, source links).
9. **Phase 13 & 14**: Run full regression suite, typecheck, lint, build, and verify zero regressions against R1-R4.5.
10. **Phase 15**: Update documentation and generate the comprehensive Release 4.6 Final Report.
