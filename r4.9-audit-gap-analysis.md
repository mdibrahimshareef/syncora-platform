## 3. Gap Analysis for Release 4.9 Objectives

| Objective | Existing Implementation | Identified Gap | Proposed Minimal Change | Verification Plan |
|---|---|---|---|---|
| **1. Memory Relevance** | `getScopedMemories` in `memory.ts` returns latest memories sorted by `updated_at DESC`. | No query-aware relevance scoring, no freshness decay, no precision filtering; stale or irrelevant memories can displace relevant ones. | Add `scoreMemoryRelevance` and `rankAndFilterMemories` with token overlap, recency decay, confidence weighting, and verification status. | Unit tests in `memory.test.ts`, precision benchmarks in `r4.9-intelligence-quality.test.ts`. |
| **2. Evidence Grounding** | `fuseEvidence` resolves basic DB status conflicts. `buildDecisionComparison` records evidence strings. | No automated verification of claims against retrieved records; no abstention on ungrounded claims or missing citations; limited conflict detection. | Add `validateRecommendationEvidence` with source verification, contradiction detection, and explicit abstention triggers. | Unit tests in `evidence-fusion.test.ts`, grounding scenarios in R4.9 evals. |
| **3. Outcome-Informed Ranking** | `ai_decision_outcomes` stores user action and outcome evaluation in `outcomes.ts`. | Outcome records are never fed into recommendation prioritization; no ranking function, no defense against feedback loops or sparse data bias. | Implement `rankRecommendationsWithOutcomes` using empirical Bayes smoothing (Laplace prior) with fallback to evidence/urgency when samples < 3. | Tests in `decision-support.test.ts` and `r4.9-intelligence-quality.test.ts`. |
| **4. User Personalization** | `ai_memories` supports `user_preference` category with `scope='user'`. | No unified preference management (detailLevel, personalization toggle, outcome ranking toggle); no intent-override precedence rules. | Add `src/lib/ai/preferences.ts` with typed preference contracts, CRUD helpers, intent-override logic, and opt-out support. | Preferences suite and authorization tests. |
| **5. Personalization Effectiveness** | R4.8 regression dataset V1 (8 scenarios). | Lacks scenarios measuring memory relevance precision@K, preference adherence, intent override, outcome ranking, and personalization opt-out. | Create `EVALUATION_DATASET_V2` with 15 rigorous scenarios in `r4.9-intelligence-quality.test.ts`. | Automated benchmark suite in Vitest. |
| **6. Security & Invariant Gates** | R4.7/R4.8 RLS policies enforce isolation on `ai_memories` and `ai_decision_outcomes`. | Must ensure new ranking and preference pathways preserve strict workspace and user boundaries without leakage. | Add negative authorization tests for preferences, cross-workspace outcome ranking, and prompt injection defense. | Security regression suite. |
