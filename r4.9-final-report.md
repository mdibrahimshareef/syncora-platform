## 1. Executive Summary & Release Identity

SYNCORA AI Release 4.9 advances the platform from durable execution and observability (established in Releases 4.6–4.8) into high-fidelity intelligence quality. While prior releases established real database RLS, resilient background queues, structured cost attribution, and trace correlation, Release 4.9 focuses squarely on the **substance and reliability of AI reasoning**:

1. **Context-Aware Memory Relevance:** Replaced crude substring matching with a deterministic 4-factor scoring model ($S_{total} = w_r S_r + w_f S_f + w_c S_c + S_v$) combining query lexical overlap, exponential decay freshness, memory confidence, and verification boost, while strictly excluding superseded and expired memories.
2. **Evidence-Grounded Recommendations & Abstention:** Enforced hierarchical evidence verification (Authoritative DB > Organizational Memory > Semantic Docs > Inferences). The system cross-references referenced entity statuses, detects contradictions (e.g., claiming a task is active when the DB marks it completed), and explicitly **abstains** when evidence is missing or conflicting rather than hallucinating.
3. **Outcome-Informed Ranking via Empirical Bayes:** Implemented recommendation ranking that adjusts confidence based on actual historical user actions and observed outcomes within the same workspace. Using a Laplace-smoothed empirical Bayes formulation ($\frac{k + 2}{n + 4}$), it prevents small-sample volatility while boosting proven recommendation types and penalizing persistently rejected strategies.
4. **User-Controlled Personalization with Strict Precedence:** Added typed user preferences (`detailLevel`, `preferredCategories`, `excludedMemoryIds`, `enablePersonalization`, `enableOutcomeRanking`), a dedicated configuration UI in the AI assistant panel, and strict precedence hierarchy: Security > DB Truth > Prompt Intent > User Preferences > System Defaults.
5. **Versioned Evaluation Suite (`EVALUATION_DATASET_V2`):** Established 15 deterministic multi-turn evaluation scenarios across 5 intelligence dimensions in `tests/ai/evals/r4.9-intelligence-quality.test.ts`.

## 4. Memory Relevance Engine (`src/lib/ai/memory.ts`)

### Deterministic Relevance Scoring Model
Each candidate memory is scored according to:
$$S_{total} = w_r \cdot S_r + w_f \cdot S_f + w_c \cdot S_c + S_v$$

- **Query Relevance ($S_r$):** Token overlap ratio between normalized query terms and memory content + category bonus ($+0.25$ if memory category directly matches detected query intent).
- **Continuous Freshness ($S_f$):** Exponential decay using continuous half-life ($t_{1/2} = 30\text{ days}$):
  $$S_f = \exp\left(-\frac{\Delta t \cdot \ln 2}{30 \times 86400}\right)$$
- **Confidence Weight ($S_c$):** Base memory confidence recorded at creation time ($c \in [0.1, 1.0]$).
- **Verification Boost ($S_v$):** $+0.15$ for `verified` memories, $+0.0$ for `unverified`, $-0.25$ penalty for `disputed`.
- **Lifecycle Filter:** Any memory with `lifecycle_status === 'superseded'` or `lifecycle_status === 'expired'` or whose `expires_at` timestamp is before the current moment is unconditionally removed prior to context injection.

## 5. Evidence Grounding & Contradiction Handling (`src/lib/ai/evidence-fusion.ts`)

### Authority Hierarchy
1. **Level 1 (Authoritative DB):** Verified database records (`tasks`, `projects`, `milestones`, `time_entries`).
2. **Level 2 (Organizational Memory):** Human-verified agreements, decisions, working rules.
3. **Level 3 (Semantic Documents):** Unstructured docs, wikis, summaries.
4. **Level 4 (Inferred Summaries):** LLM conjectures, ungrounded heuristics.

### Validation Engine (`validateRecommendationEvidence`)
- **Contradiction Detection:** If a recommendation claims a task is active or needs urgent rescheduling, but the Level 1 DB evidence records the task status as `completed` or `cancelled`, the claim is flagged as an active contradiction.
- **Due Date Discrepancy:** If the recommendation asserts a due date conflicting with the DB record by $> 0$ hours, it flags a temporal discrepancy.
- **Explicit Abstention:** Rather than fabricating facts, the validator sets `shouldAbstain = true` with a clear executive reason:
  - *"Recommendation contradicts verified database evidence."*
  - *"Insufficient verified evidence in workspace for referenced entity #ID."*
- **Executive Explanation Template (`formatGroundedExplanation`):**
  ```markdown
  ### Recommendation
  [Clear action statement]

  **Why this matters:**
  [Business impact grounded in workspace state]

  **Evidence:**
  - [Verified DB / Memory point 1]
  - [Verified DB / Memory point 2]

  **Uncertainty & Assumptions:**
  - [Any unverified claims or missing data]

  ---
  **Suggested Next Steps:**
  1. **[Step 1]**
  2. **[Step 2]**
  ```

## 6. Outcome-Informed Recommendation Ranking (`src/lib/ai/outcomes.ts`)

### Empirical Bayes Formulation
To rank candidate recommendations without suffering from small-sample variance:
$$\text{SmoothedScore} = \frac{\text{positiveCount} + 2}{\text{totalCount} + 4}$$

- **Sample Size Floor ($n \ge 3$):** If a recommendation type has fewer than 3 historical recorded outcomes in the current workspace, it is considered in the **cold start** regime. The system defaults to base urgency and evidence strength without applying an outcome multiplier.
- **Outcome Multiplier:**
  $$\text{multiplier} = 0.5 + \text{SmoothedScore} \in [0.5, 1.5]$$
  $$\text{FinalScore} = \text{baseUrgencyWeight} \times \text{evidenceStrength} \times \text{multiplier}$$
- **Hard Workspace Boundary:** `rankRecommendationsWithOutcomes` filters historical outcomes strictly by `workspace_id`. Outcomes from other organizations or workspaces are mathematically isolated.

## 7. User Personalization & Preferences System

### Data Model (`src/lib/ai/preferences.ts`)
```typescript
export interface UserAIPreferences {
  detailLevel: 'concise' | 'balanced' | 'comprehensive';
  enablePersonalization: boolean;
  enableOutcomeRanking: boolean;
  preferredCategories: MemoryCategory[];
  excludedMemoryIds: string[];
  updatedAt?: string;
}
```

### Precedence Hierarchy
1. **Security & Workspace Isolation:** Hard database isolation and RLS rules. Cannot be overridden by any preference or prompt.
2. **Authoritative DB Truth:** Live task/project state overrides memory and preferences.
3. **Explicit Query Intent:** A query explicitly asking *"Give me a 1-bullet summary"* overrides a saved `comprehensive` preference.
4. **Saved User Preferences:** Custom detail level, preferred memory categories, and excluded memory IDs.
5. **System Defaults:** Balanced detail, all categories permitted, outcome ranking enabled.

### UI Implementation (`src/components/ai/AIPreferencesModal.tsx` & `AIAssistant.tsx`)
- Integrated a discrete preferences button (`SlidersHorizontal`) directly in the `AIAssistant` header next to the new chat button.
- Clean modal providing toggles for Detail Level (`concise` / `balanced` / `comprehensive`), Personalization Enable/Disable, Outcome Ranking Enable/Disable, and a single-click Reset to Defaults.
- Backed by secure REST endpoints at `/api/ai/preferences` (`GET`, `POST`, `DELETE`) with workspace membership verification.
